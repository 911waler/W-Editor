# 网页粘贴 RGB 样式在刷新后显示源码

## 现象

网页内容携带 RGB 颜色与字号时，粘贴后重开文档会显示 `!16 !!rgb(93, 93, 93) …!!!` 等内部标记。用户还报告粘贴时偶发报错；本次复现未出现该报错，不能认定完全同因。

## 原因

已确认：浏览器 HTML 粘贴产生的 RGB 颜色被富文本序列化器直接写入 Cherry 标记，但共享读取规则只接受颜色名称与十六进制颜色。字号嵌套颜色时，内层无法识别，导致整段标记显示为正文。修复前的真实剪贴板事件测试和重开测试失败，十六进制对照正常。

## 处理方式

- 共享 `richInlineMarks.ts` 识别合法的逗号分隔 RGB（通道 0–255），字号和前景/背景色支持嵌套。
- 新序列化、旧内容投影及 Cherry 渲染入口将 RGB 转为十六进制颜色。
- 读取时不修改文档原始源码，不运行数据库迁移；代码块与行内代码保持原文。
- 同步至本机独立 W-Editor 工作副本 `/tmp/w-editor-sync-20260930` 的共享核心与测试。
- 本次为源码修复；尚未部署生产，尚未推送 GitHub。Windows 独立软件接入和测试沿用此前约定留待 Windows 环境。
